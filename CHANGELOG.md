## 0.10.0 - 2026-09-11

- 换锁不换门，堵上了：`verify_task` 开头新增治理代码对账（AGF 对账三件套——坐标申报/对账/降档棘轮——的第一个实例）。`GOVERNANCE_CODE_PATHS` 列出决定 verify 判罚本身的八个模块（tasks/checks/review/config/slicer/acceptance/hazard/scheduler，各自职责见代码注释）；canonical 在任务开工后推进了其中任何文件、而 worktree 未包含该更新（纯落后）时，verify 被拒绝并列出落后文件、提示从 canonical 运行 `ag2c task refresh` 后重验——进程内的 auto-refresh 只能换磁盘字节，换不了已经在跑的旧代码，所以这个检查刻意排在 HEAD 分叉自愈之前。worktree 自己改了这些文件不算落后（那是任务内容本身；双方同改由既有 canonical-head-diverged 相交检查接管）；比对本身出 git/IO 故障降级为 `governance-code-reconcile-degraded` intervention 留痕，不阻塞 verify；拒绝时记 `governance-code-behind`（带 paths 与双侧 head）。动机：2026-09-11 事故——`policy.regulator.strict` 默认值翻转（e042028）合并后，仍有 4 次 verify 被翻转前开工的 worktree 用旧代码在监管 401 时放行（账本 17:41-18:05 UTC），治理收紧不回溯在途任务。Covered by `GovernanceReconcileTests`（落后被拒+干预记录 / 领先放行 / canonical 只动非治理文件时并行税自愈照旧 / 手动 refresh 后重验放行 / 比对故障降级不阻塞）。

- Scheduler Phase 1 (shadow mode): `ag2c/scheduler.py` gains `shadow_plan()` — a pure function that computes what a future selective-verify *would* skip, without skipping anything. Given the planned checker ids, the full checker roster, the current change digest, and the ledger events, it emits an `ag2c.shadow-plan.v1` plan: per-checker `{id, planned, shadow: run|skip, reasons}` entries plus a `would_skip` list. Reasons are `slice-selected` (planned, no usable cache), `unchanged-inputs` (a passed verify exists for this exact change digest and this checker passed in it), and `not-in-slice` (not planned — shadow and reality agree, so it does not count toward `would_skip`). `verify_task` computes the plan after the checker set is known, prints a one-line stderr summary (影子计划：本会跳过 X/Y 个 checker（缓存命中），本次仍全跑), and stores the plan in the verification record — which lands in the `task-verification` ledger payload, giving Phase 2 its observation data. Any error inside the shadow computation degrades to `{schema, mode, error}` and never blocks verify. Deliberately out of scope: no real skipping, no depends_on/import relevance (Phase 2), no trust levels (Phase 3), no obligation queue (Phase 4), no regulator prompt change. Covered by the new `test_scheduler.py` suite (cache-hit skips / different digest runs / failed history never skips / unplanned skips as not-in-slice / green history missing the checker runs / wiring: plan lands in verification record + ledger event, and a same-digest re-verify reports every checker as would_skip while still running all).

- 动态预算的超标警告不再硬化成门（9.7 硬化分流）：`_budget_warnings` 生成的 over-budget 警告新增 `budget_source` 字段——`explicit`（policy 显式 budget_lines，人工定价）或 `dynamic`（动态仓快照；chars/ast_nodes 派生维度跟随其父预算来源）。硬化判定经新的 `_escalatable()` 分流：dynamic 来源的警告照常计数留痕但永不硬化（动态快照注定随增长型房间自然长个儿过期——快照过期不是违抗）；explicit 来源维持第三次出现硬化；`budget_source` 缺失的警告（旧历史、verify_costs 秒预算）按 explicit 处理，行为与现状一致。计数指纹不含 budget_source，所以房间从动态转人工定价后，既有计数 ≥3 的警告下一次出现立即硬化——价格对话到期。动机：2026-09-11 tests 房间事故——覆盖率自然增长 338 行顶破动态快照（13699 vs 13361），第三个携带该警告的不相关任务被门拦住；budget-recalibrate 的棘轮只紧不松，动态房间的超支事实上没有自动出口。Covered by `DynamicBudgetEscalationTests`（动态五次不硬化仍计数 / 人工第三次硬化 / 缺失来源维持旧行为 / 动态转人工后立即硬化）与 `MultiDimensionBudgetTests` 的生成侧三例（explicit 标记 / dynamic 标记 / 混合来源逐维度分流）。

- 4.4 沉默不是警情，落地: the hazard board gains two new sources. `guard-removed` (severity 60, the new top) is the guard heartbeat — for enrolled projects (activation.json present), `core.hooksPath` pointing anywhere other than the store's `state/hooks`, or the hooks directory going missing, raises an alarm the moment the guard is down instead of after the fact. `ungoverned-commit` (severity 45) is the trunk trailer audit: commits landing on the registered trunk after the ledger's first event without an `AG2C-Task:` trailer are listed one by one (short sha, subject, author) — the mayor's own direct pushes included, because the system cannot tell the mayor from a guard-removing attacker; `govern hazard-dismiss` is the acknowledgment channel, with the usual sunset. Both degrade to silence on any git/store error, and both skip unenrolled projects. Covered by `GuardHeartbeatTests` (match+dir present silent / unset / wrong path / dir missing / unenrolled silent) and `UngovernedCommitTests` (trailer exempts / no-trailer flagged with fields / empty ledger no baseline / pre-baseline exempt / no trunk skips / both kinds dismissible).

- Portraits can now be amended mid-task instead of forcing an abandon-and-restart: `ag2c task amend-portrait --portrait-file <f> --actor <a> --reason <r>` (MCP twin `ag2c_task_amend_portrait`) re-lints the new portrait, replaces the locked one in the task record, and records a `portrait-amended` intervention — actor, the mayor's named correction, and the old/new portrait digests — in the ledger. Identical portraits, lint failures, and terminal tasks are refused with the old portrait untouched. The regulator sees the amendment history as a prompt section (occurred_at / actor / reason / digest pair per amendment; unrelated interventions stay out) and is asked to judge each amendment as mayor-named correction vs self-serving drift. Motivation: the 2026-09-10 D→D2 restart, where a wrong portrait caliber (≤60s vs the real ≤90s budget) could only be fixed by abandoning the task and re-locking from scratch. Covered by the new `test_portrait_amend.py` suite (replace+intervention+ledger / lint refusal keeps old / actor+reason required / identical refused / terminal refused, plus `EntryPointTests` driving the real CLI dispatch and the MCP handler+schema), `AmendmentPromptTests` and a feed-through test in `test_review.py` (history block renders; empty amendments leave the prompt byte-identical).

- The warning-escalation gate gains its legitimate exit: `ag2c govern warning-dismiss --key <key> --actor <a> --reason <r>` removes a warning's accumulated count from `state/warning-history.json` (matching the user-facing `key` shown in gate errors, not the internal fingerprint) and appends a `warning-dismiss` ledger event carrying the key, the dismissed counts, actor, and reason. Dismissal means "acknowledged", not "fixed" — the count restarts from zero, so a recurring problem escalates again. Unknown keys are refused with a non-zero exit. Also fixed two misleading comments: `hazard.py` now says what 4.3 actually means (沉默本身即警情, matching `review.py`), and the `checks.py` timeout call-site comment no longer claims a closure where a direct call lives. Covered by `WarningDismissTests` (count restart after dismissal / unknown key refused / ledger event fields).

- Verification structure refactor: `tests/suites.py` now delegates suite execution to pytest + pytest-xdist (install with `pip install .[test]`), collecting the existing `unittest.TestCase` suites natively and distributing tests across CPU cores (`-n auto --dist loadgroup`). The gui and fast suites stay serial — gui because imgui tray tests are not worker-safe, fast so the Windows spawn tax cannot eat its per-module smoke budget — and `tests/conftest.py` pins the gui suite's modules to an `xdist_group` derived from `SUITES["gui"]` itself (single source of truth — a new gui module cannot escape the serial pin), so full-run invocations keep them on one worker. Measured on the maintainer's machine: the full 635-test run finishes in ~85s (was ~18-25 min serial under the old runner), and per-suite checker wall-clock drops up to 19× (this task's verify `checker_durations`: rehome 543s → 28.6s, enrollment 92s → 19.0s, governance ~150s → 33.2s; standalone suite runs on a loaded machine read higher, e.g. enrollment ~59s) — shrinking the exposure window in which environmental slowdowns (antivirus scans, background load) could push a suite into its timeout.
