# AG2K 对 AG2C 的启发：行为准入与认知准入的对照

> 背景：AG2K（AutoGovern2Knowledge）是项目家族中管"知识准入"的兄弟——
> observe → propose → admit 流水线，admission 不暴露给 AI，签名离线发布。
> AG2C 管"行为准入"（代码变更过 verify 门）。本文把 AG2K 摆到 AG2C 面前对照，
> 但结论不是"抄它的闸门"，而是它在信任阶梯上的位置。
>
> 状态：第二轮对照结论（2026-09-11 讨论确认，含 holo 的出身纠偏），待逐条转化为设计任务。

## 一、对照总览：同一个东西的两半，而且出身相反

AG2C 治行为：代码变更必须过 verify 门（机器校验 + 监管）。
AG2K 治认知：知识必须过 admission 门（observe → propose → admit）。

关键在出身：**两者最初是反过来的**。

- AG2K 从**零信任起点**出发：最悲观，完全不信任 AI，知识从 0 开始，
  逐条 observe、propose、admit 向上爬——静态的零信任准入。
- AG2C 从**动态信用演化**出发：先跑起来，出错追责；追责对 AI 失效
  （无威慑感受器），被逼出预防机制与棘轮——信用在实战中涨落。

一个是"先不信，慢慢挣"，一个是"先跑着，出事就拧"。方向相反，恰好互补。

## 二、启发 1：信任阶梯——AG2C 管降档，AG2K 管升档

AG2C 现有的全是**降档机制**：棘轮只下不上、危房名单、过期卡、警告升级。
缺的是**升档机制**——一张卡怎么从"AI 刚写的草稿"长成"可信知识"？

信任阶梯（可信度升级方案）：

- **L0 proposal**：AI 写卡即提案（AG2C 现状，actor+reason 落账）。
- **L1 机器锚定**：provides 锚定真实符号、普查新鲜（AG2C 已有）。
- **L2 实战存活**：被 N 个任务的 reuse_menu 引用、被 portrait 依赖，
  且这些任务 verify 全过——**每次成功复用就是一次升级投票**，
  票数和事故率都从账本里长出来，不需要谁额外打分。
- **L3 AG2K 准入**：只有爬到顶的卡才进 AG2K 辖区，过完整的
  observe → propose → admit，admit 不暴露给 AI、离线签名——
  成为"宪法级"知识。

所以 AG2K 要**置后**：它不是现在抄进 AG2C 的闸门，而是阶梯顶端的
收官机制——多次升级的升级管控。AG2C 朝下拧，AG2K 朝上拧。

衔接点（三兄弟在此闭环）：AG2K 的 observe 阶段可以直接**读 AG2C 的
账本**——哪张卡被引用多少次、带没带来事故（接上 AGF 阶段 3 的按事故率
校准）。admission 决策有实证输入，不是凭空审。AG2C 产证据，AGF 定坐标，
AG2K 守顶门。

## 三、启发 2：离线签名 → 可信基循环的外部锚点

AG2C 的账本、收据、portrait 全在 store 里，而 store 在 AI 的活动半径内——
信任根在爆炸半径里，这是 4.1（可信基循环，S 级）的循环。

AG2K 的答案是**签名离线发布：信任根放圈外**。搬过来就是：
定期把 ledger digest + 知识卡 digest 做一个离线签名的快照，verify 时校验。
AI 在圈内怎么折腾，都伪造不了圈外的锚。

## 四、启发 3：小内核 → 信任核心瘦身

AG2K 是个小工具，准入手核小到一个人能审完。这示范了一条原则：
**信任成本正比于可信基大小**。

AG2C 越来越大，verify / ledger / regulator 这些信任关键路径应该隔离成
最小可审核心，其余全是可替换外围。

## 五、反向攻击：阶梯的由来

为什么不能全量照搬 AG2K？因为 AG2C 每个任务都可能动卡，张张走
admission 会把用户变成瓶颈，违背主线图景"终点是用户，仅限判断"。

正是这个反向攻击**生出了阶梯**：全量 admit 不可行，所以 AG2K 置后，
只接被实战反复验证浮到顶部的卡；底部和中部留在 AG2C，事实下沉到机器
（锚定、普查、账本统计），判断上浮到用户（只有 L3 准入和分拣标准本身
需要人）。分拣标准本身，就是政策沙盘（正面机制 6.1）的好题目。

## 六、AGF 反投影：decider 洞 B 的复现

这本质上是 AGF 七维里 decider 维度的问题：AG2K 把知识 admission 的
decider 钉死在 human/offline，AG2C 知识卡的 decider 目前是 AI 自己。

反投影测试发现的洞 B（decider 缺 AI 裁决档且单值）在这里又冒出来了——
说明那个洞是真的，不是测试的假阳性。阶梯恰好给出修法：decider 不该是
单值，而该**按层级分档**——L0/L1 是 machine，L2 是账本统计（machine
+ 证据），L3 是 human/offline。
