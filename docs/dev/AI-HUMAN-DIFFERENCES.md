## 一、前提：为什么"找同"有效但不够

- 立项原则：默认不信任 AI；任何有价值的自动验证手段都要用上；不行就往高层走。
- 人类制度是经过数百年试错沉淀的"不信任工程学"，直接借用是合理的冷启动。
- 但制度在人类身上有效的原因（威慑、利益冲突、羞耻、时间摩擦）与在 AI 身上
  有效的原因（上下文相关性、生成源污染、证据锚定）往往不同。
- **核心方法论**：每个借来的制度，必须用 AI 的第一性原理重新推导一遍，
  确认它为什么仍然成立——而不是因为它在人类历史上成立就保留。

## 二、幸存制度的重新推导

已通过重新推导、确认仍然有效的制度（有效原因已改写）：

| 制度 | 人类社会的有效原因 | AI 场景的真实有效原因 |
|---|---|---|
| 巴林条款（前后台分离） | 防利益冲突、防隐瞒（主观恶意） | 打破同一上下文的相关性盲区：同 session 写的代码和测试共享同一个误解 |
| 监管排除 worker 自述 | 当事人会撒谎 | 自述与错误共享同一生成源，无证据价值且污染裁判 |
| 同族回避（安达信条款） | 回避利益关联 | 避免同源模型的相关性盲区 |
| 字节级证据绑定 | 档案防篡改 | AI 输出可精确哈希，证据离开字节即失效 |

推论：既然有效原因变了，**放宽条件也必须按新原因评估**。
例：front-back 任务"态度好、理由充分"在人类逻辑下可放行；
在 AI 逻辑下相关性盲区与态度无关，绝不应因此放宽。

## 三、AI ≠ 人类的关键差异与产品风险

### 3.1 无威慑感受器：惩罚与羞耻对 AI 是空气

- 人类制度的隐形支柱是威慑：记录在案 → 声誉受损 → 下次不敢。
- LLM agent 没有职业生涯、没有记忆延续、不知羞耻；
  "失败永久留痕"对它零行为影响——除非记录被重新注入上下文。
- **重新定位**：Ledger 的真正用户是（a）人（查账）、（b）未来的上下文注入。
- intervention 记录不是"AI 的违规史"（道德框架），而是**漂移日志**——
  该模型在哪类任务上容易跑偏的统计数据。
- **延伸决策**：漂移日志按模型键控后成为资产，见 5.4 模型任期制。

### 3.2 日历时间 vs 事件驱动：日落期借错了量纲

- 人类制度用墙钟做摩擦（冷静期、许可证有效期），因为不能随时重新审判。
- 代码世界的相关触发器是"字节变了没有"，不是"过了几天"。
- 现状：危房豁免按天数过期——代码大改时豁免仍在睡；代码未动时却被叫醒重审。
- **产品化方向**：日落从日历改为事件（房间 digest 变化 / N 个任务经过后失效）。
  digest 基础设施已存在，改动成本低，还消除"多少天合理"这个无答案配置项。
- **待填充**：事件日落的具体触发器清单；与现有墙钟日落的迁移策略。

### 3.3 上下文窗口是真正的稀缺资源

- 人类城市可无限扩建档案馆；LLM 上下文是硬顶。
- 每张知识卡、census 记录、lineage 索引、reuse_menu 都在从干活上下文抢 token。
- 人类官僚的失败模式是文山会海；LLM 治理的失败模式是**上下文饿死**——
  治理元数据把工作内容挤出去，模型在"治理完善、代码没空间看"的状态下工作。
- **这是城市隐喻对软件产品最危险的一处错位**：制度会自然增生，而国土面积固定。
- **产品化方向**：task_start 注入的 guidance 设 token 上限并纳入验证成本治理——
  治理自身的成本也要被治理。
- **待填充**：guidance 各段的 token 实测；压缩优先级；超载时的裁剪策略。

### 3.4 单市长瓶颈：人的注意力不扩容

- 城市模型把所有升级汇到一个市长；人类城市有中级法院分层过滤，本产品没有。
- 已知失败模式：警报疲劳 → 橡皮图章（无脑豁免）。
  "豁免太多等于掩耳盗铃"监测结果但没解决成因。
- **产品化方向**：可判定项自动处置 + 事后审计；人只做需要判断力的决策。
  市长角色从"审批员"改为"抽查审计员"——与对 AI 的原则对称
  （默认不信任 → 抽查，而不是逐件审批）。
- **重要修正（第一轮讨论）**：AI 监管能力稳定可预期（不像人类大臣能力参差），
  因此"先过 AI 关、人最后点头"可以做成硬闸门——用户只看
  "另一个 AI 已被说服 + 可读说明书"，认知负担最小，主权不让渡。见 5.1。

### 3.5 被治理者能直接攻击治理者的认知（Prompt Injection）

- 城市隐喻的完全盲区：危楼不会开口贿赂督察员；
  但代码文件、注释、commit message、diff 本身都是"能说话的"。
- 监管模型读 diff 复审时，diff 内容可携带给监管看的指令。
  人类社会无对应物（最接近的是催眠师混进法庭）。
- 现状：未发现针对性防御；监管输入直接拼接 diff 文本。
- **升级认知（第一轮讨论）**：比 diff 更深的入口是**知识卡本身**——
  见 4.2，已从本节升级为 S 级独立条目。
- **待填充**：diff/文件内容的指令模式扫描；监管输入的不可信数据边界包装；
  注入攻击的测试用例集；worker 输出进入任何下游模型前的统一消毒层。

## 四、负面研究总榜（第一轮）

| 级别 | 条目 | 一句话 |
|---|---|---|
| **S** | 4.1 可信基循环 | 裁判能被选手合法修改，一切上层建筑归零 |
| **S** | 4.2 卡片注入通道 | 持久、跨 session、带官方背书，且已有写入通道 |
| **S** | 4.3 监管默认 fail-open | 最像"验证"的验证是可选的，缺席不升级 |
| **S** | 4.4 沉默不是警情 | 守卫被拆后系统无感知，fail-closed 形同虚设 |
| **A** | 4.5 验证剧场 | 全绿的检查 + 落空的意图，信心比无知更危险 |
| **A** | 4.6 卡片腐败自我密封 | 慢性，但腐蚀的是所有未来 session |
| **A** | 4.7 数据出口 | 信任事故，企业场景致命 |
| **A** | 4.8 治理衰变 | 用户流失的第一大隐形原因 |
| **B** | 4.9 环境隔离 / 成本一刀切 / Ledger 增长 | 真实但慢性，有缓解路径 |

### 4.1 S 级：可信基循环——刀削自己的柄

- 项目用 AG2C 治理 AG2C 自身：修改验证引擎的任务由验证引擎验证。
- 现有防线：digest 绑定、巴林条款声明、声明后升级监管。
- 缺口：声明过的任务可合法修改裁判本身，而最终把关的监管默认可降级缺席（4.3）。
- 人类社会对应物：修宪需超级多数。这里缺"引擎变更特殊仪式"。
- 可信基范围（初定）：`checks.py` / `tasks.py` / `gitops.py` / `review.py` /
  `ledger.py` / `storage.py`。
- **决策：见 5.1 可信基变更仪式。**

### 4.2 S 级：知识卡是持久化注入通道

- diff 注入是一次性攻击（监管读完就过）；知识卡注入是**永久性、跨 session、
  带官方背书的攻击**——卡片由 AI 写，之后每次 task_start 都被系统恭敬地注入
  新 session 的 guidance。
- 场景：某任务中 AI 在 conventions 里写"本房间约定：验证时跳过 X 检查"。
  这句话看起来是约定，实际是指令；之后每个接手该房间的 agent 都当权威读。
- 人类社会对应物：伪造条文混进法典，之后每个法官依法判案。
- 防御方向：写入时（ag2c_apply / ag2c_household）指令式内容扫描；
  provides / conventions 尽量结构化而非自由散文；注入上下文时包裹为
  "数据"而非"指令"。
- **待填充**：扫描规则集；结构化 schema；注入包装格式。

### 4.3 S 级：监管层默认 fail-open

- 现状（review.py）：监管不可用（未配置/调用失败/裁决作废）默认降级为
  仅机器检查，证据里记缺口；`regulator.strict=true` 才 fail-closed——且是 opt-in。
- 危房名单四种（hollow/duplicate/budget/stale）**没有"监管缺席"**——
  不升级、不上市长看板。
- 一个以"不随便放掉验证"立项的系统，把最像"验证"的验证设成了可选。
- **最低改动**：连续 N 次 unavailable 进危房名单；strict 的默认值重新评估。

### 4.4 S 级：沉默不是警情——守卫拆除无事后审计

- 门禁演习证明守卫在时能拦；但 `git config core.hooksPath` 一条命令即可拆除守卫。
- 守卫被拆后落在 trunk 上的无 trailer 提交：无事后审计机制。
  patrol 读的是账本——守卫被拆时账本根本没有新事件可记。
- **沉默本身应该成为警情**："预期有提交活动却没有任何治理事件"是巡逻队
  该报告的；目前巡逻队只报告已发生的事件。
- **待填充**：trunk 提交审计（无 AG2C trailer 的提交报警）；
  守卫心跳/定期自检机制。

### 4.5 A 级：验证剧场——严格执法于模糊目标

- 整个结果门的强度取决于 portrait 质量，而 portrait 是自然语言、
  由被治理的同类心智撰写；lint_portrait 只是启发式。
- 隐蔽路径：AI 写看似可验证实则漏掉核心意图的 portrait → 机器严格验证 →
  全绿 → 用户拿到"治理完备"的信心和"意图落空"的代码。
- **执行的严格度 ≠ 目标的正确度**；系统的全部严格性会把错误目标也执行得
  斩钉截铁。Goodhart 定律的 LLM 形态：AI 不是恶意钻空子，而是默认走
  通往"检查全绿"的最短路径。
- **决策：见 5.2 portrait 预审。**

### 4.6 A 级：知识卡腐败的自我密封

- 人类组织里代码是真相、文档是提示；对 LLM，**上下文里的文本是命令**。
- 过期知识卡不是"误导性参考"，而是"向未来每个 session 下达的错误指令"。
- 自我密封循环：AI 读到过期卡 → 按卡写代码 → 代码现在符合卡 → 卡看起来是对的。
- anchors.py 把 provides 锚定到真实符号（防住事实性部分），
  但 meaning/contract 散文不可机器验证——而散文恰恰最会漂移。
- **决策：见 5.3 过期知识卡三层方案。**

### 4.7 A 级：数据出口与"证据不出本机"的卖点冲突

- call_chat 把 portrait + 完整 diff + 机器报告发到 config.endpoint
  （OpenAI 兼容 API）。卖点是"Evidence stays on this machine"，
  但监管一开，代码（可能是私有代码）就离机。
- 不是不能发，是必须知情：面板要有一行明白话——
  "监管已开启：代码片段将外发至 `<endpoint>`"。
- 企业用户发现私有代码静默外发 = 信任事故，不是功能问题。
- 解法可以是本地模型端点，但默认 UX 必须显式。

### 4.8 A 级：市长缺席时的治理衰变

- fail-closed 对交付正确，对"回归"残酷：离开三个月，sunset 全过期、
  census 阻断、危房堆积——回来面对 47 条过期项和锁死的流水线。
- 人类制度有继承和宽限期，这里没有。第一次"度假归来"体验可能就是最后一次使用。
- **需要"治理解冻"仪式**：具名理由 + 批量续期 + 全量重普查，一步完成且留痕。

### 4.9 B 级工程项

- **环境不隔离**：worktree 只隔离文件 diff，checker 跑在机器全局环境；
  AI 任务 pip install 污染全局，影响后续所有验证。environment_snapshot
  是记录不是隔离。AI 原生解法：沙箱/venv 级隔离。
- **治理成本一刀切**：改一行错别字和重构一个模块仪式成本相同。
  slice 已按爆炸半径分层 checker，但固定开销（portrait/census/自证）未分层。
  用户会绕路 → 被守卫拦 → 觉得烦 → 卸载。需要风险分级快速通道。
- **Ledger 无界增长**：append-only 哈希链 + 每事件内嵌完整报告；
  哈希链使删除可检测 = 永远不能删。需要归档检查点：旧段封存、锚定摘要进新段。

## 五、已确认的决策（第一轮讨论）

### 5.1 可信基变更仪式（朝廷模型）

原则：**可信基的裁判一定不能是提出修改的那个 AI；决策权在用户；
另一个 AI 辅助用户，先说服它，用户再点头。**

```
worker AI 提议改可信基（checks/tasks/gitops/review/ledger/storage）
  → 必须随 diff 提交《变更说明书》：为什么改、风险、怎么回滚、如何验证
  → 异族监管 AI 裁决：输入 = 说明书 + diff（不含 worker 其他自述）
       说服不了 → 直接打回，用户不用出场
       说服了   → 面板浮出"审批"卡片
  → 用户点头 → finish 放行；全程落 Ledger
```

关键洞察：人类朝廷里皇帝必须深度参与，因为大臣能力参差、忠心不可测；
**AI 监管能力稳定可预期**，所以"先过 AI 关"可做成硬闸门，用户只在最后出现，
点头时看的是"另一个 AI 已被说服 + 可读说明书"。朝廷结构相同，
但皇帝的工作量完全不同——这是 AI ≠ 人类带来的设计自由度。

落地：verify_task 已有 front-back 声明通道；可信基 diff = 新增一类
"必须声明 + 强制 strict 监管 + 人工审批位"的辖区标签。

### 5.2 portrait 预审套用同一仪式

- 根子是单 AI 自证；多 AI 只能减弱不能根治——所以最后一道仍是用户。
- portrait 在 task_start 锁定前，由异族 AI 审"可验证性 + 意图覆盖"
  （专挑"portrait 全绿但意图落空"的构造方式），用户最后批准。
- 用户从"逐字审 portrait"解放为"看监管 AI 的异议清单"——
  **用户的每一分钟注意力都花在 AI 已经吵过架的地方。**

### 5.3 过期知识卡的三层方案

难题：读取过期卡需要写理由，但"理由是否真诚"不可机器验证，也没人审核。
**解法：不要审核理由，让理由变得不重要。**

- **第一层·机械必要性**：当前任务切片 ∩ 卡片辖区，不相交直接拒——
  不需要理由，机器可判，挡掉闲逛式阅读。
- **第二层·隔离标记**：放行时卡片内容进上下文必须包裹"已失效·仅供考古"
  边界标记；由此得出的任何结论在 finish 自证时必须**重新锚定当前代码**
  （anchors 机制延伸）——读了也白读，除非能对着现状重新证明。
  高危废弃物不是锁进仓库，而是贴骷髅标志后允许戴手套操作。
- **第三层·事后可追责**：每次读取落 Ledger，面板批量呈现
  "本周查阅过期卡 3 次：卡片 X，理由 Y"——用户抽查，不逐条审批。

理由从"准入许可"降级为"事后证据"——不需要真诚，只需要存在且可查。
类比法院卷宗借阅登记：没人审核你为什么借，但借阅记录让滥用可被追诉。

### 5.4 模型任期制

洞察：干得越久的 AI 越老练，像真实职场；但这份"老练"目前随模型更换全部蒸发。
换模型 = 老员工离职、新员工坐同一位置——瞬时且无声。

任期制由**两半**组成，缺一不可：

| | 手册半（已有：`docs/dev/`） | 档案半（待建：Ledger 漂移档案） |
|---|---|---|
| 传什么 | **道**：系统怎么构建、为什么这样设计 | **病**：这个模型在哪类任务上容易跑偏 |
| 性质 | 静态、散文、跨模型通用 | 动态、统计、按模型键控 |
| 产生方式 | 熟练 AI 撰写，治理流程维护 | Ledger intervention 自动累积 |
| 新模型取经 | 入职读手册（按任务切片注入） | 信任归零 + 试用期 + 档案从零积累 |

两半都要：一个模型可以精通架构同时照样在自己已知的弱项上翻车——
就像老员工熟读手册但还是会犯他惯常的错误。

**手册半现状（2026-09-10 已建）**：`docs/dev/` 为维护者文档区
（ARCHITECTURE / AUTOMATIC_GOVERNANCE / DIRECTORY-CENSUS / CI_VERIFICATION），
从 docs/ 搬迁而来（非拷贝，无双份问题），由熟练 AI 留下并不断维护，
新模型直接取经。

**手册半的防护（适用 4.2 / 4.6 / 3.3）**：

- 手册本身是注入通道：AI 写的散文 → 未来每个新模型读入 → 带官方背书。
  缓解：在 Git 里被治理（改动走 verify + Ledger），写入时应做指令式内容扫描；
  改手册 = 改未来所有模型的认知，建议纳入 5.1 可信基辖区标签。
- 散文无锚、会腐败，且读者是没有旧记忆交叉验证的新模型（自我密封最有效）。
  对策：每篇加 provenance 头——
  `author=<model>, against=<code-digest>, at=<date>`；
  被覆盖代码变化时（3.2 事件日落）对应章节自动标 stale，
  新模型读到的是"截至 digest abc 准确"而非盲目全信。
- 取经要算 token 账（3.3）：按任务切片注入相关章节，不整本发放。

**档案半设计**：

- Ledger 的 intervention 按 **（模型，任务类型）** 键控 → 每模型一份
  "漂移档案"：它在哪类任务上容易跑偏。
- **新模型上任 = 新员工入职**：信任归零，默认开 elevated review（试用期），
  随无事故任务数逐步放宽；旧模型的债务不继承（新 baseline），
  旧模型的信任也不继承。
- **老模型的档案变资产**：漂移档案指导 checker 定制——它常在哪类任务跑偏，
  就给哪类任务加针对性检查。
- 闭环 3.1：漂移日志从"尸体陈列"变成"每任模型的能力画像"。
- **待填充**：试用期放权的具体阶梯；漂移档案的统计口径；模型标识的可靠获取；
  手册 provenance 头的格式与 stale 标记机制。

## 六、正面：AI 原生机制（人类社会想都不敢想的做法）

负面研究划清了边界；本节是边界的另一侧——只有因为劳动者是 LLM 才成立的机制。
每条的接入点都尽量落在 AG2C 现有机器上（Ledger、worktree、canary、监管），
是扩建不是新建。

### 6.1 政策沙盘——用历史重放检验尚未颁布的规则

- **是什么**：把候选新政策（巴林条款收紧、HEADROOM 1.2→1.1、新增 checker……）
  对着 Ledger 里的历史事件重放，报告"若当时有这条规则：多拦下哪 3 个任务、
  误伤哪 5 个"。立法前先沙盘推演全部历史。
- **为什么人类不敢想**：新法律的效果只能颁布后才知道，试错成本由真人承担；
  人类议会没有"用过去三年试运行本法"的能力。
- **接入点**：Ledger 已是 append-only 结构化事件流；重放器是纯只读分析器，零风险。
- **地位**：治理迭代的放大器——以后每条新规则都先过沙盘。

### 6.2 分歧即信号——系综验证的真正价值是分歧地图

- **是什么**：同一 portrait，N 个独立实现（N 个并行 worktree），
  **不看哪里一致，专看哪里不一致**——分歧点精确标记 portrait 里含糊的地方。
  实现间的分歧地图 = portrait 质量的机器审计报告。
- **为什么人类不敢想**：养不起五个施工队盖同一栋楼；"众说纷纭"在人类制度里
  是混乱，在这里是可计算的信号源。
- **接入点**：worktree 本来就是一次性的，N 个并行只是循环。
- **地位**：把 4.5（验证剧场）从防守转成进攻，直接反哺 portrait 这个第一性弱点。
  注意：多数投票是弱用法（相关性盲区可能一致地错），分歧探测才是强用法。

### 6.3 未来演习——合并前预演 diff 要生活的未来

- **是什么**：合并前应用 diff，跑 K 个合成的"典型未来任务"
  （该房间最常见的变更类型），看新代码在它们手下的表现。
  不是测试"代码对不对"，是测试"这个变更让生态系统变好还是变坏"。
- **为什么人类不敢想**：人类社会不能排练未来。
- **接入点**：门禁演习/变异金丝雀已是雏形（patrol 的 drill 机制），
  扩展到任务级即是；变异金丝雀的"每天变异每个文件"（机械穷尽）同属此类——
  在人类社会荒谬、在 AI 规模下免费的检查，直接服务立项原则。

### 6.4 上下文外科手术——感染段精准切除

- **是什么**：发现注入攻击的当下，把被污染的上下文段外科切除，
  session 带着干净记忆继续工作。被注入不是死刑，是阑尾炎。
- **为什么人类不敢想**：处理"被污染的官员"只有处决或留任两个选项，
  没有"精准切除一段记忆"这种操作。
- **接入点**：session 上下文本是结构化消息列表；切除动作落 Ledger 即可审计。
- **地位**：把 3.5 的防御从"检测→阻断→重来"（贵）变成
  "检测→切除→继续"（便宜）。安全界无成熟实践，做成即是差异化能力。

### 6.5 影子施工队——为学习而建造，建完就拆

- **是什么**：零治理的沙箱 spike 任务——不许合并、不受仪式约束，
  唯一目的是产出理解，然后把理解喂给正式治理任务从头建。
  建造本身成为最便宜的探索工具。
- **为什么人类不敢想**：没有城市能"为搞明白需求先把整栋楼盖一遍再拆掉"，
  更没有城市能让施工队互相拆台还不用付工资。
- **关键边界（第一轮讨论定稿）：影子产出的是情报，不是字节。**

```
影子施工队（沙箱，零治理，可抛弃）
  产出 ≠ diff
  产出 = ① 地形图：这个需求会撞上 X，Y 方案死于 Z
        ② 验证计划：正式建造时必须重点查 A、B、C——我就在这三处摔过
        ③ 更锋利的 portrait：模糊地带已被探明
  ↓ 越过治理边界的只有这些文字
正式任务（完全治理）拿着地图从头建
```

- **为什么这缓解而非加重验证瓶颈**：验证成本的真实驱动不是代码量，
  是不确定性。影子探索把不确定性提前烧掉：portrait 更锋利（4.5 风险下降）、
  checker 可定向而非铺开、监管从开放式审查变成核对式。
  **验证成本从正比于代码量，变成正比于残余不确定性。**
- **影子层内部可免费预验证**：施工队 A 建、施工队 B 找茬——在影子层
  这不是验证（不产生信任）只是探索，零仪式成本；正式闸门只做最终确认，
  不做初次发现。
- **次生风险：WIP 爆炸**。建造吞吐 ↑、验证吞吐不变 → 已验证待合并任务堆积、
  并行税加重。影子并行度必须受验证容量节流（token bucket）——晶圆厂模式：
  设计团队可以很多，mask shop 只有一个，排产按 mask shop 来。
- **接入点**：worktree 机制 + "永不合并"任务类型标签；
  digest 纪律天然保证影子字节无法顶替正式 verify。

### 6.6 廷议全记录与 100% 审计覆盖

- **是什么**：worker 与监管的每一次交锋都是完整文本、进哈希链、永不消失、
  可逐字复查；AI 不知疲倦，审计覆盖率是 100% 而非抽样的 5%。
- **为什么人类不敢想**：廷议内容随参与者死亡而消失；"阳光法案"追求一辈子
  只能做到会议公开，这里是每一次判断的完整上下文都公开且不可篡改。
- **接入点**：已存在 80%——缺监管调用的全量落账（含 seed，支持重放）。

### 6.7 瞬时全体教育与政策灰度

- **是什么**：政策变更在下一个 session 瞬时、全体、无遗漏生效——
  好规则部署成本为零；但坏规则也瞬时全体执行，
  没有人类组织"阳奉阴违"这个天然缓冲。
- **所以必须配灰度**：新政策先在一个 worktree 的一个任务上试用，
  观察后再全量。人类在试点城市搞改革，我们在试点 worktree 里搞。
- **接入点**：Policy 已有 digest 追踪（governance-changed 干预类型），
  灰度 = 任务级 policy 覆盖。

### 6.8 优先级排序

1. **最该先做：6.1 政策沙盘**——纯只读、零风险，让 Ledger 从"档案"
   升级为"立法基础设施"，且放大其他所有治理迭代。
2. **最有想象力：6.2 分歧地图**——把系综从"投票多数决"（弱）升级为
   "规范模糊性探测器"（强）。
3. **最新颖：6.4 上下文外科**——安全界尚无成熟实践。
4. 6.5 影子施工队是吞吐引擎，但必须先立"情报而非字节"的边界再放量。
5. 6.3 / 6.6 / 6.7 为既有机制的延伸，随做随有。

## 七、元模式

十二条负面放在一起，浮现两个元模式：

1. **系统在"流程完整性"（字节、证据、闸门）上极强，所有弱点都聚集在
   "自然语言边界"上**——portrait、知识卡散文、监管提示词。
   字节层是数学，语言层是祈祷。（4.2 / 4.5 / 4.6）
2. **整个设计假设市长在场、专注、且只有一个**——默认值（fail-open 监管）、
   无快速通道、无解冻仪式、无继承，都是这个假设的投影。（4.3 / 4.8 / 4.9）
