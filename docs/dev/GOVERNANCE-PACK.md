# 治理包与反向开发（主指导）

> 地位：外管真正要做成的东西。GUI 不是主题，见文末与 [GUI-RETIREMENT.md](GUI-RETIREMENT.md)。
> 本文落地不等于已经改播种器、已经抽出 flatten 模板、已经对外管量过效果。
> 作者：grok，2026-09-14。待市长点头后按「实施顺序」开刀。

---

## 0. 什么最重要

AG2C 的价值不是托盘，也不是再给每个仓库手写一份 `suites.py`。

真正要做成的是两件事：

1. **治理包（默认、零副作用）**  
   每个被管项目在工程**外面**有一份属于它的包：知识卡片 + checkers + 检测脚本。三样一起才生效。用户不反向开发也可以，卸掉就整包拿走，仓库里没有 AG2C 痕迹，程序按原来的方式跑。

2. **反向开发（可选）**  
   从 AG2C 自己那套里抽出模板：排队拆胖子、抽模块、搬运门证明没偷改。在复印件上改源码，跟正本对比，告诉用户改了什么，点头才合。边干边把「改哪跑哪包测试」记进治理包，立法者长在包里，不是长在用户源码里。

执法者始终是同一套：副本施工、Git 门禁、按 checkers 跑命令、不过不合。  
立法者每本工程一本，写在治理包里，条文只能**指向**考卷（包内脚本，或用户仓库里已有的测试），不能改成「必须 `python -m ag2c` 才能考」。

---

## 1. 最小单位：三样，必须同包

AG2C 管自己能转，靠的是：

| 样 | 干什么 | AG2C 自己现在住哪 |
|---|---|---|
| 知识卡片 | 这间房/这个文件是什么 | 门外 `policy.json` |
| checkers | 改这里跑哪条命令（挂号单） | 同一份 `policy.json` 的绑定 |
| 检测脚本 | 对错怎么判 | 仓库里的 `tests/`（因为 AG2C 首先是软件） |

管别人时，三样一开始往往都没有。**家必须在一起**：默认都在**该项目的治理包**（店外档案 + 包内考卷），不要卡片、checkers 在门外、考卷却摊进用户 Git 才算「生效」。

- 没有卡片：不知道改到哪。
- 没有脚本：没有对错。
- 没有 checkers：执法者看不见该跑谁。

checkers 单独成一份，不是多此一举：脚本是考卷，卡片是说明书，checkers 是挂号单（id、命令、超时、是否 always、绑哪些卡）。同一条检查可绑多间房；脚本在用户仓库或在包里，挂号单永远在门外。

**合进用户仓库不是生效的前提。** 合进去只发生在用户接受某次反向开发（拆文件、或自愿把测试收成自己的代码）。

## 2. 两条轨道

### 轨道 A — 只挂治理包（立项默认）

1. 入学：工程外建档案，Git 挂钩。正本一个字都不改。
2. 普查：把目录画成房间（黑盒就标黑盒），卡片写在包里。
3. 若用户没有测试：考卷写在**包里**，对着用户源码跑（import 用户代码，文件不进用户 Git）。
4. checkers 指向这些包内命令（或用户仓库里已经存在的 `pytest`/`unittest`），绑到卡片上。
5. 卸掉 = 删包 + 摘钩。用户文件夹里不应留下 `.ag2c`、不应留下我们塞的测试。

不反向开发也没问题。门在，法在包里，源码仍是屎山也可以。

### 轨道 B — 反向开发（用户要摊、要拆时）

1. 复制一份源码当工地（worktree 就够；大摊可以用长期同一块复印件）。
2. 用从 AG2C 抽出的模板干活：排队最肥最热的文件、抽模块、源文件变门面、**flatten-check** 卡住「新行必须能在删行里找到」——对不上就不是搬家。
3. 没有最小考卷时，考卷仍优先写在治理包里；只有用户说「这些测试我要收进仓库」才合进正本。
4. 边干边更新治理包：这间房绑哪条检查。立法者跟着真实结构长。
5. 对照正本用人话账单：哪些是搬家、哪些是新考卷、哪些动了行为。点头再合源码；不点头正本不动。
6. 工地可拆。源码改动若已合，住在用户 Git；法仍住在治理包。下次日常改动不必重新整仓进工地。

反向开发**不能**把用户项目接到 AG2C 源码树下。AG2C 的树是工艺母本，不是客户代码的家。

---

## 3. 立法者 / 执法者

- **执法者（可同一套）：** hook、worktree、跑 checkers 上的命令、账本、finish。便携目录里那份运行时。拆掉 AG2C 这个 Git 仓库，执法核仍应能挂在「包 + 钩子」上（长期形态）；至少卸掉后产品不依赖 `import ag2c`。
- **立法者（每项目不同）：** 治理包里的卡片 + 绑定 + 考卷指向。不能把 AG2C 自己的 `tests/suites.py` 房间名单抄给别人。
- **不干预用户代码：** 立法是指向，不是改写。checkers 的 `command` 必须是用户的测试命令或包内脚本，**禁止**默认写成 `python -B -m ag2c seed run`（那是执法者跑进用户考卷，已偏过一次）。

AG2C 自己：立法（卡片+checkers）已在门外档案；`tests/` 留在仓库，因为那是产品测试，不是「演零副作用」。典范是结构，不是把自己变成空仓库再外挂考卷。

---

## 4. 播种与「树」长到哪

阶段是**看出来的**，不是日记本画的：planted → mapped → growing → sliced。

- `sower=ag2c`：挂号单是 AG2C 按规矩写入包、命令为原生命令。
- `sower=foreign`：人手写 `suites.py` 一类，切开也不信任。
- `sower=host`：AG2C 本体，不许按外管 sow。
- `trusted`：仅 ag2c 播种且 sliced。

机器能强行：拆胖子、搬运门锁行为、把已有测试夹登记进包。  
机器不能编：土里没有的 404 事实、产品该长什么样。那是方向，人点头。

效果（外管是否真让人少盯、产品是否不依赖 AG2C）**尚未在真项目上量过**。夹具绿了不等于外管成功。

## 5. 现在缺什么（相对本文）

已有：执法（worktree/hook/verify）、AG2C 自己的反向开发（flatten-queue/split/check）、门外卡片与绑定、播种器雏形（但命令曾指向 `ag2c seed run`）、verification_growth / seed status。

还缺、且应排在 GUI 前面：

1. **治理包形态：** 包内可放检测脚本；checkers 指向包或用户原生命令；卸包无源码痕迹。
2. **sow 纠偏：** 只写门外挂号单，命令不得默认 `-m ag2c seed run`。
3. **flatten 对外模板：** 队列不得写死 `src/ag2c`；对工地里的用户源码排队。
4. **账单：** 工地 vs 正本，用人话区分搬家 / 新考卷 / 行为改动。
5. **真项目量一回效果**（治理包挂上、可选拆一刀、卸掉后产品仍跑）。

CartridgeFlow 上手工 `tests/suites.py` 是 foreign，不能当成功样板。

## 6. 实施顺序（点头后）

GUI 相关一律靠后。

| 顺序 | 做什么 | 完成长什么样 |
|---|---|---|
| 本文档 | 主指导 | 你能接受或打回 |
| P1 治理包 | 包目录约定；考卷可住包内；checkers 绑原生命令或包内脚本；卸载摘净 | 夹具项目：无用户仓库测试也能跑包内考卷；卸包后用户 Git 无新文件 |
| P1 sow 纠偏 | `ag2c seed sow` 只写 `unittest discover` / `pytest` 等 argv | 夹具 sower=ag2c 且 command 不含 `-m ag2c seed` |
| P2 反向开发模板 | flatten-queue 对准任意工地根；split/check 不变 | 对夹具胖子文件能排队、抽走、搬运门过 |
| P2 账单 | 工地 diff 分类输出 | 用户能看见搬家 vs 行为改动 |
| P3 外管实测 | 选一个真仓库走轨道 A，可选 B 一刀 | 有账：卸包后产品仍启动；合入仅发生在用户点头 |
| 其后 | 解惑 Skill / 可选 brief / 再考虑 GUI | 见 GUI-RETIREMENT.md |

P1 两刀是立法者能不能对外成立。P2 是反向开发能不能当模板。P3 才是「我们知道效果」。没有 P3 不要宣称外管成功。

## 7. 不做

- 不把用户源码接到 AG2C 仓库下面再「分离」
- 不把 AG2C 自己的 `tests/` 拆出去演零副作用
- 不把手工 CF `suites.py` 当成 AG2C 播种
- 不默认把检测脚本合进用户正本
- 不以 GUI 为外管主路径
- 不在本文档任务里改播种器或删托盘
