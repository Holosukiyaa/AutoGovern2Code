### 托管模式（市长代理层）——2026-09-11 晚与市长定稿

**定义**：托管模式 = 市长不看「需要你处理」，看「代理正在做什么」。仪表盘重心从决策队列翻转为代理活动流。市长的动词只剩三个：**看**（代理活动流）、**否**（否决窗口）、**授**（授予新代理权）。

**现状**：显示层已就绪（注意力闸门 t42／三区 t51／颜色纪律 t52／警情必达 285ac0b／托盘双心跳）；**代理层空白**——2026-09-11 实战市长被摸 6-8 次，仅约 2 次真需人判（杀 QQ、预算口径裁决），其余是机械事项走人工通道（settle 清零、full-scan 确认、已知良性警告认领）。

**三块建设**：

1. **决策分类学**：列出所有会摸到市长的点位，逐个判「规则可决 / 必须人决」——账本即实证材料，AGF 试飞数据用于校准。
2. **代理规则引擎**：每个自动决定落账并带授权规则 id，可审计可撤回；代理权的授予记录本身进账本（代理权是市长授予的，不是系统自取的）。
3. **抽查回火**：代理决定进随机抽查池（接 t911 既有机器）——代理权不被审计就会变成篡权。

**信任阶梯合流**：代理权按 AG2K 梯子爬——L0 提案规则（默认关闭）→ L1 机器锚定（规则落 policy）→ L2 实战存活（N 次代理决定零否决）→ L3 常备授权。**托管模式是 AG2K 从抽象概念变成日常操作的地方**。

**安全序**：代理权先覆盖可逆周界（settle／普查／警告认领）；不可逆动作（合并／删除）永远留人。

**北极星**：市长介入次数/天 → 0-1。挂成本治理「高效」腿（6bba67e 的仪表已预留位置）。

### 反向开发机制（摊平）——2026-09-11 与市长定稿

**起因**：单文件膨胀对 AI 维护者是双重税——胖文件废掉「文件名=语义摘要」的注意力路由，且每个碰它的会话都多烧 token（经济腿驱动因子）。实测分布：40 文件中 8 个 >800 行的文件占 57% 代码量（健康尾巴：28 个文件 <400 行）；**当日三个交互事故（amend×finish 死路→tasks.py 2160 行、census cwd 脚枪→mcp_server.py 1245 行、缓存 key 碰撞→households.py 926 行）全部发生在 >800 行的胖头**——文件超过单次注意力容量后交互 bug 滋生。

**现状盘点：治理语法全是正向的**

| 操作 | 现有机制 | 方向 |
|---|---|---|
| 加功能 | 任务回路全家桶 | 正向 ✅ |
| 移动文件 | `ag2c_rehome`（git mv + 全仓 import 重写 + 门禁） | 侧向 ✅ |
| 删除残留 | `retire` / `retire-confirm` | 反向，只管目录残骸 |
| 卡片清算 | 全量清算 | 反向，只管卡片不管代码 |
| **拆分/摊平代码** | **无** | **反向 ❌** |

房间预算是 GDP，文件软帽是基尼系数——只量总量时单文件可以在绿灯房间里癌变。预算体系的结构性盲区。

**机制四件套（detect → queue → operate → verify）**：

1. **发现**：src/ag2c 单文件 >800 行出警告（只警告不硬化，老规矩）——把盲区补成仪表。
2. **队列**：按「热度 × 肥胖度」排序；冷胖文件不碰不拆（boy scout：谁被任务碰到谁拆）。
3. **操作**：借 rehome 的 import 重写机器，加「提取集群 → 新模块 → 重写引用」split 原语。facade 先行：tasks.py 留 50 行 re-export，测试与 import 方不动，验证拆分后再清理。
4. **验收——纯搬运门**：摊平任务测试全绿是必要不充分；真正要回答「它只是搬运吗」。机器可验形式：**新增行必须全部来自删除行**（逐行哈希对账，豁免 import 行与模块 docstring），逻辑改动一行不许混入。比正向任务验收更硬更机械——摊平的正确性定义就是「什么都没变」。

## 4. 操作手册（血泪版）

- **普查 cwd 脚枪**：MCP `ag2c_census` record=true 必须显式传 `cwd=<worktree 路径>`；不传默认 canonical，finish 不认（6d85939 后 canonical 录制会出 warning 字段，注意看）。
- **MCP server 版本偏斜**：server 是长驻进程，合并新代码后旧进程继续跑旧代码。症状：finish 报 census-stale 但普查明明是新的。处置：`cursor-agent mcp disable ag2c && cursor-agent mcp enable ag2c`，然后**重启 CLI 会话**（`cursor-agent --continue`）——disable/enable 只修配置层，活会话不会重连。CLI 兜底：verify/census 都可从 worktree 跑 `python -B -m ag2c ...`。
- **PowerShell 陷阱**：内联 `python -c "..."` 引号会被吃——驱动脚本写成 .py 放 `%TEMP%` 再跑；`>` 重定向产出 UTF-16LE（读出来是乱码/BOM），解析前先转码。
- **finish 窗口纪律**：census 新鲜（worktree 录、覆盖任务改动）+ verify 新鲜 + 其间无治理写/canonical 移动。canonical 动了 → `ag2c_task_refresh`（MCP，参数名是 `task`）→ 重录普查 → 重验 → finish。
- **全量验收门**：治理面变化触发全量时需 `task declare --full-scan --reason ...` 申报（落账），然后重验。
- **监管在线且严格**（DeepSeek，strict=true）：自证每条有副作用的声明必须引用本会话工具输出（命令+输出片段）；「测试过了」无输出=不交。
- **环境险情**：Windows 剪贴板是全局共享资源，任何软件持锁都会崩 gui 套件（见 backlog #1）。verify 卡 check.suite-gui 原生崩溃时先怀疑剪贴板，别怀疑代码。
- **并行会话**：多会话并行跑 verify 会互相踩负载（check.python 预算已按负载口径锚 35s）；发新委托任务前确认在飞任务数量。
