# 代理人治理：从 25 分钟的脚本说起

> 来源：2026-09-10 晚 holo 与 agent 的设计讨论，经市长过目。
> author=holo(研究圆桌), against=a88afa8, at=2026-09-10
> 地位：与 AI-HUMAN-DIFFERENCES.md 并列的优先级依据；本文档是其元模式②
> （假设市长在场、专注、唯一）的正面解答。

## 1. 病例：一个脚本跑了 25 分钟

2026-09-10，一次全量 verify 跑了 25+ 分钟且两次假性失败。事后解剖：

- 静态 timeout 按单跑拍值（180/600/900s），checker_parallelism=4 是后来为提速调的——两个旋钮同处 policy，互不知晓；九套件并发互拖，全部撞上限（exit_code=null、耗时恰等于上限），同代码串行全绿。
- 动态秒预算机制早已存在（实测×1.5 报警），但超支只警告不阻断；警告出现两次无人处理，第三次自动升级为全局锁死。
- 行数预算同理：docs 刻意增长（市长批准的研究文档入库）触发超支，但家庭房间没有任何合法抬预算的通道，警告从"可行动"拖成"死锁"。
- 最后由市长的体感完成"发现"：他注意到"一个脚本要跑 25 分钟"，亲自下场问为什么。

一个病例，四种病：梯子倒置、警告到人的最后一米断裂、阻断没有主人、市长注意力被花在机制上。诊断所需的每一个字节都在系统内部，但系统选择的最上报通道是**让市长忍受**。

## 2. 梯子成本不变量

逐级上报的设计隐含不变量：**每一层必须比上一层便宜一个数量级**。

- L0 静态/diff 检查：秒级
- L1 测试脚本：十秒级——存在理由是"近乎免费地筛掉 95%，让贵层只看值得的 5%"
- L2 监管 LLM：分钟级
- L3 市长：全系统最贵

病例当天 L1 要 10-30 分钟、L2 只要 1 分钟——脚本层比监管层贵 10-30 倍，梯子倒了；且 L2 排在 L1 后面空等。治理系统的长期生存能力 = 验证成本是否持续低于绕行冲动；门越严（strict 默认化），门就必须越便宜，否则严格的门活不下来（4.8 治理衰变的经济机制）。

## 3. 便宜的三个来源与门的总时延信封

便宜不是脚本的天然属性，来自三个可性质，病例当天全部丢失：

1. **可选择性**——只跑相关的（丢失：套件绑房间，改一行跑 182 个测试）；
2. **可跳过性**——没变就不跑（丢失：重试 verify 输入 digest 不变也全量重跑）；
3. **可并行性**——多核白捡的加速（丢失：并行撞静态 timeout，被迫串行）。

预算侧盲区：秒预算按单个 checker 棘轮，每个可涨 1.5 倍才报警，新套件自由绑入——**没有任何对象对门的总时延负责**。修复：信封预算作为一等公民，市长定死（建议起点：切片 ≤2 分钟、全量 ≤10 分钟），超信封即危房；绑新套件会撑爆信封时绑定动作被门挡住，先瘦身再加。与行数预算"禁止增长"同构，对象从房间换成门。

## 4. 知识卡是注意力地图

卡片系统（楼层/房间/户口、depends_on、provides、import 索引）的设计初衷是给 AI 的注意力划地盘——上下文贵，隔离是精髓。verify 今天只用了卡片的皮（房间绑套件），没用骨（depends_on 爆炸半径、import 相关性、provides 货架）。**验证注意力应是同一张地图的镜像**：diff 落在哪几个房间、沿关系波及哪几个，验证就只看这些；失败报告按卡切片，修复的 AI 只需加载失败房间的上下文。

## 5. 调度器六职责（市长原话扩展）

1. **上下文隔离的执行者**：以卡片图为调度输入，不是文件列表。
2. **纯代码机制**：schedule(diff, 卡片图, 历史仓) → plan 是纯函数，确定、可单测、天然高可信、低维护——与监管 LLM 形成对称美。
3. **多 AI 并行不打架**：冲突图调度——计划房间不相交则真并行，相交才排队；锁粒度从整台机器细化到房间×套件。
4. **可信等级逐层变严**：新卡/刚挂过的卡=试用期=全量严审；连续绿=更宽缓存窗口；一次失败立即降级。信任机械地从账本算，不许 LLM 掺和。
5. **巡逻队**：每个 plan 落账本——跑了什么、跳了什么（机械理由）、耗时 vs 预算、有没有抓到过东西。六个月零捕获的 checker 是 4.5 验证剧场的机械探测器，也是瘦身的数据依据。
6. **阻断的主人**：每次升级生成有主、有期限、有唤醒（notify）的义务项；后续 verify 开头先报"上次的 X 还没人认领"，逾期拒绝调度新工作。阻断从没人负责的副作用变成调度器的故意行为。

铁律：调度器决定"什么不跑"，是信任敏感操作——跳过逻辑永远机械（只认 digest 和 import 图）、保守过包含、skip 列表进报告给监管看；调度器自身的代码变更走 4.1 可信基仪式。

## 6. 代理人：四器官

调度器升级为市长的执行代理。市长只提交意图、验收结果；其余全部代理。

| 器官 | 职责 | 现有胚胎 |
|---|---|---|
| 手（调度器） | 验证计划、排队、执行、留痕 | 第 5 节 |
| 权（授权矩阵） | 哪些决策自决、哪些上报 | 待立法 |
| 责（义务队列） | 每个异常有主、有期限、有跟进 | settle 队列的被动版 |
| 口（汇报协议） | 定期摘要 + P0 中断，其余静默 | notify（仅 2 个调用点） |

授权矩阵四档（以 2026-09-10 真实事件分类）：

- **机械类**（自决，只记账）：普查、settle、过期卡同步、预算重锚。docs 预算超支本应由代理人追溯原因（市长批准的文档入库）→ 自动锚定 → 留痕，而不是把市长拉出来点按钮。
- **判断类**（处理，摘要列示）：警告豁免（带日落）、重试策略、套件绑定调整。
- **价值类**（带提案上报，市长只做选择题）：新房间、信封预算、删除自有内容、信任政策。
- **宪法类**（4.1 仪式）：可信基、宪法卡、代理人自己的代码。

## 7. 三层注意力

市长注意力是全系统最贵的资源，默认一分不花。

1. **必须注意到**：自己意图的结果验收（项目出口，不可折叠不可错过）+ P0 中断（带提案的选择题，首次警告即弹，而非锁死后）。
2. **抽查层**：不靠市长记得翻记录，系统端上样本——代理人每个动作开回执（情况/依据/动作/结果/可撤销性），有闲时端上 3 张随机回执各附一问"这个处理你认可吗"，30 秒一张，结论落账本。抽查是授权矩阵的校准器：认可率高→该类自主权放宽；否决→立即收紧一档且理由沉淀为规则。注意力投入越少系统越保守，投入越多且认可越多系统越大胆，永远可一夜收回。
3. **默认不看**：原始队列、危房处理过程、例行统计——存在、可查、不推送。

看板首页重排：验收队列 → P0 中断区 → 代理人直播条（可选）→ 抽查入口 → 心跳健康数；异常清单/危房/settle 队列退到 drill-down。

## 8. 三条风险（必须点名）

1. **代理人放大"沉默不是警情"**：吸收决策越多，自身漂移越没人看见。心跳与 audit 抽检是代理人合法性的前提，先有心跳后有代理。
2. **验收橡皮图章化**：验收界面直接渲染 portrait 的 Surfaces 清单（每个面：示例+空态/错态/成态），市长对着清单验收，不是对着"通过了"三个字。
3. **打回通道必须比上报通道宽**：市长的权力主要是否决；"这类结果不对"要能成为规则沉淀进授权矩阵，不是一次性修补。

## 9. 落地路线

- Phase 0（止痛）：timeout 从动态秒预算单源派生×并行度联动；本机 verify 互斥。
- Phase 1：schedule() 影子模式——只打印"本会跳过什么"不真跳，观察数轮。
- Phase 2：相关性+缓存转正；信封预算立法。
- Phase 3：信任等级；多 AI 冲突并行。
- Phase 4：义务队列接管升级跟进；授权矩阵立法；看板三层重排。

最终形态：市长说"我要什么"，代理人说"做好了，验收清单在这"，市长说"行"或"不行"——中间的一万次治理动作，市长一辈子不必看见。
