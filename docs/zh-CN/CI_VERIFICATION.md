# 本机证据与 CI

AG2C 把完整治理证据放在项目外部。这是“用户工程零治理文件”带来的明确取舍。

## 本机证据绑定什么

每个完成任务都会在外部工程目录保存一份自摘要凭证，它绑定：

- 起点提交、最终路径、Git 文件模式和精确内容；
- 最终责任路由和验收状态；
- 可信检查命令与结果；
- 当时使用的 Manifest 和 Policy；
- 失败尝试、AI 纠正和被阻止的动作；
- 最终提交与哈希链 Ledger 事件。

提交消息只写入 `AG2C-Task` 和 `AG2C-Evidence` trailer。它们帮助本机找到并核对外部凭证，但不会在工程中新增文件。

## 本机复核

在管理该 clone 的机器上：

```bash
ag2c ci verify --commit HEAD
ag2c ci verify --commit HEAD --rerun
```

第一条把提交和本机凭证核对；`--rerun` 还要求当前正好位于该提交且工作区干净，然后重新计算路由、确认检查计划并再次运行检查。

普通用户直接看托盘。`ag2c evidence` 是给 AI 和维护者的等价只读入口。

## 远端 CI 能证明什么

全新的 CI Runner 只有 Git 历史，没有开发者的外部治理目录。证据摘要只能标识一份存在的凭证，不能凭空还原它。因此 AG2C 不再发布一个假装“只靠 Git 就能复核本机完整证据”的复合 Action。

远端 CI 应独立运行项目自己的测试、Lint、构建和安全检查；多人仓库应保护集成分支并把这些检查设为必需项。这样能证明提交在 CI 机器上的产品质量，但不能证明开发者本机的完整施工历史。

可移植、可签名的证据导出属于以后多人版的能力。它需要明确的传输和信任模型，不能为了方便又把治理内部文件塞回每个项目。

## 信任边界

本机证据能证明 AG2C 记录的路由、检查、精确内容和集成彼此一致。它不能证明项目选择的检查一定充分，也不能替代操作系统安全和远端仓库管理员权限。
